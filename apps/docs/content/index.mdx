# Wire UI

Wireframe primitives for modern JavaScript frameworks. Each component is like a wireframe that ships to production — pure structure, behaviour, and accessibility with zero CSS. You bring the design; Wire UI handles everything else.

## Why Wire UI?

Most component libraries bundle design decisions you can't escape. Wire UI takes the opposite approach: every component is a bare wireframe — a lightweight behaviour primitive with no visual opinion. You get the interaction logic, keyboard handling, ARIA attributes, and state tracking. Nothing else. No stylesheets, no CSS variables, no theming layer.

Think of it as starting from a wireframe instead of a finished design. You sketch the final look with your own CSS, Tailwind classes, or whatever styling approach you prefer — targeting `data-*` attributes that reflect every interactive state.

```tsx
// Wire UI ships no styles — just the wireframe:
<Button onClick={handleClick}>Save</Button>

// You paint the wireframe with your own styles:
<Button className="
  px-4 py-2 rounded bg-blue-600 text-white
  [data-hover]:bg-blue-700
  [data-active]:scale-95
  [data-focus-visible]:ring-2
  [data-disabled]:opacity-50
">
  Save
</Button>
```

## Core principles

**Wireframe primitives.** Every component is a lightweight, unstyled building block — zero CSS shipped, zero design opinions. Like a wireframe, it gives you the structure and leaves the visual design entirely to you.

**State via `data-*` attributes.** Every interactive state (hover, focus, active, disabled, open/closed) is exposed as a data attribute — empty string when active, absent when not. Style with CSS attribute selectors.

**Compound components.** Complex widgets follow the `Component.Part` pattern. You compose the markup, control the order, and add whatever wrapper elements you need.

**Consumer-owned validation.** Form components expose `invalidType` and `errorMessage` props but perform no validation internally. Set `invalidType` when your validation logic decides it's invalid — the component renders the error state.

**`asChild` for polymorphism.** Pass `asChild` to Button to merge all props onto your own child element — great for router links and icon buttons.
